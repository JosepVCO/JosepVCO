## 👋 Hi there

I worked on the integration side of a data platform: REST API and webhook
problems, connector configuration, ETL and Reverse ETL pipelines, and onboarding
enterprise clients. The part I enjoy most is turning a messy customer
requirement into a pipeline that runs without anyone touching it.

I'm now moving deliberately toward **building the tooling, not just debugging it.**

## 🛠️ What I do

| | |
|---|---|
| 🔍 **Troubleshooting** | REST API, webhook, connector and pipeline issues, with root cause analysis and clear reproduction steps |
| 🔗 **Connectors** | Configuring API fields, merging datasets, removing deprecated fields, validating extraction |
| 🤝 **Customer-facing** | Technical onboarding, turning data requirements into production-ready setups |
| 🧪 **Proofs of concept** | MongoDB transformations that remove integration blockers |

## 🚀 Tools I'm building

I build these for three reasons: to solve the day to day problems I met at
work, to turn what I learn into YouTube content, and to create tools that make
my own projects more efficient and easier to navigate.
Everything uses public APIs and synthetic data.

| Project | What it does | Status |
|---|---|---|
| 🧬 **hubspot-postgres-sync** | Incremental HubSpot → PostgreSQL sync with pagination, rate limit handling and a Reverse ETL mode | 🗓️ Planned |
| 📣 **meta-ads-extractor** | Facebook / Instagram Ads metrics via the Meta Graph API, with token expiry handling and error triage | 🗓️ Planned |
| 🪝 **webhook-validator** | Verifies signatures, validates payloads against a JSON Schema, replays failed events | 🗓️ Planned |
| ⚙️ **api-connector-config** | Config driven API extraction: add or remove fields through YAML, not code | 🗓️ Planned |
